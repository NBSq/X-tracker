# x-narrative-tracker v1.0.0

Release date: 2026-08-07

## Highlights

- Stable local-first pipeline for X, RSS/Atom, generic feeds, and local JSON content.
- Deterministic mock AI plus optional OpenAI structured analysis and signal reasoning.
- SQLite-backed signals, history, outcomes, smart rules, watchlists, graph analytics, and quality analytics.
- HTML Telegram alerts, daily reports, Excel-compatible CSV exports, and a FastAPI/Jinja2 dashboard.
- Multi-source normalization and smart deduplication into evidence-backed unified events.
- Typed internal Event Bus for extensible signal, source, outcome, graph, quality, and observability flows.
- Production health endpoints, Prometheus metrics, structured logging, and Docker/Compose deployment.
- Reusable saved searches and persisted scheduled reports with deterministic local summaries, Telegram, CSV output, and observable run history.

## Stable Scope

The v1 compatibility promise covers documented CLI flags, existing REST paths, additive SQLite initialization, the sample/mock workflow, CSV column ordering, and the primary Event Bus models. External publisher feeds and third-party API behavior remain outside the project's control.

## Upgrade From 0.x

1. Stop ingestion, dashboard, Task Scheduler jobs, and containers that write the database.
2. Copy the SQLite database and its `-wal` and `-shm` files, if present, to a backup location.
3. Update the source checkout and install `requirements.txt` in the existing or a fresh Python 3.11/3.12 environment.
4. Compare `.env.example` with your local `.env`; keep credentials out of version control.
5. Run `python -m app.main --health-report`. Startup applies additive, backward-compatible schema initialization.
6. Run the offline demo or one normal ingestion cycle, then verify `/ready`, reports, dashboard pages, and exports.

No manual database deletion is required. Keep the backup until the normal workload and dashboard have been verified.

## Known Limitations

- This is a narrative continuation and attention tracker, not a token-price or profitability predictor.
- Mock AI is keyword-based and may miss context, multilingual text, slang, sarcasm, or new tickers.
- Public RSS endpoints can change, disappear, or rate-limit clients.
- SQLite and the in-process Event Bus target one active writer/process; they are not a distributed queue/database architecture.
- The dashboard and API do not include authentication. Bind locally or place them behind an authenticated reverse proxy.
- Momentum, relationship, quality, and outcome scores are configurable heuristics and require adequate history.
- X, OpenAI, and Telegram require external credentials/network access and are optional.

## Verification

The release test suite covers database initialization, offline mock analysis, CLI version output, dashboard creation, health endpoints, exports, outcomes, graph/quality analytics, Event Bus behavior, observability, and deployment configuration. Docker build verification runs in CI because Docker may not be installed on every developer workstation.
